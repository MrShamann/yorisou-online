## 4. Fallbacks used, and why

1. **Governed-Skill fallback.** Four `yorisou-*` Skills the brief routes to are not installed. Rather than fabricate their invocation, their *functions* were performed explicitly and are traceable: governance via `project-governance-preflight`, routing via direct registry/route archaeology, review via the two installed design Skills + the brief's own review sequence, and trust-risk via the brief's §17 checklist.
2. **Preview archaeology (PR #113).** Its Vercel Preview is unreachable and its head is stale/conflicted; running it locally for archaeology was judged not worth standing up a conflicted branch when the same surfaces exist on `main` and were source-audited. Recorded as **not performed**.
3. **Local render environment.** `npm run dev` cannot render *any* route in this sandbox (`next/font/google` cannot reach `fonts.gstatic.com`), so the **production build output** was served instead. This was confirmed environmental, not code: `/` and `/tests` — untouched routes — also returned 500 in dev.
4. **Preview verification.** The Vercel branch Preview is behind deployment protection (302), which brief §21 accepts for Founder review; automated verification therefore ran against the local built server rather than by weakening any protection setting.
